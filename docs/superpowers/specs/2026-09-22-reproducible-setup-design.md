# ActiveSGM-Qwen-Planner 可复现与安全发布设计

日期：2026-09-22
目标分支：`codex/reproducible-setup`

## 1. 目标

把当前研究原型整理为一套面向 **Ubuntu 20.04 + NVIDIA GPU + CUDA 11.7** 的可复现实验入口。新用户克隆仓库后，应能按文档完成环境安装、第三方依赖准备、数据与模型路径配置、环境自检和小规模冒烟实验。

本次改造解决“代码存在但依赖、路径和运行入口不完整”的问题，不宣称已经在任意新服务器上一键完成全部论文实验，也不扩大当前实验结果的论文结论。

## 2. 已确认的缺失与约束

- 公共仓库没有实际登记可初始化的 Git 子模块，现有 `git submodule update --init` 不能补齐 `third_parties`。
- 环境文件中 `mmcv==2.0.0` 与现有 `mmdet==2.25.3`、`mmsegmentation==0.26.0` 不兼容。
- 多个脚本仍包含旧服务器的绝对路径、Conda 路径和代理地址。
- 本机找到的旧目录含第三方源码，但没有保留其 Git 元数据；不得把它们直接复制进公共仓库。
- 本机未找到可安全发布的 Replica 数据集、Qwen 权重或有效检查点；这些资产必须由使用者自行获取，并保留在 Git 忽略目录中。
- 当前 Windows 电脑不作为正式运行平台，无法在这里证明 Habitat、CUDA 光栅化扩展和完整 ActiveSGM 流程可运行。

## 3. 方案

### 3.1 环境定义

新增一个明确的 Linux 环境定义，以服务器上曾成功使用的版本为依据：Python 3.8、PyTorch 1.13.1 + CUDA 11.7、`mmcv-full 1.6.0`、`mmdet 2.25.3`、`mmsegmentation 0.26.0`，并统一 Qwen2.5 所需的较新 Transformers 版本。

安装过程分层：

1. 创建基础 Conda 环境；
2. 安装 CUDA 对应的 PyTorch；
3. 安装 OpenMMLab 兼容版本；
4. 获取并编译必要的 CUDA 扩展；
5. 运行环境自检。

脚本失败时必须立即退出并显示具体阶段，不能静默跳过失败项。

### 3.2 第三方依赖

新增 `scripts/setup/bootstrap_third_parties.sh`，只从公开上游仓库获取 Co-SLAM、SplaTAM、Habitat-Sim、neural_slam_eval 以及必要的光栅化扩展。

- 对已有可靠提交号的依赖固定到提交号；其余依赖先验证与本项目匹配的提交，再写入清单。
- 重复运行时不覆盖存在本地改动的目录。
- 第三方源码、构建产物和下载缓存不提交到本仓库。
- 每个第三方项目仍受其原始许可证约束，README 中给出来源和许可提示。

### 3.3 数据与模型

提供路径配置样例和准备脚本，但不上传以下内容：

- Replica/Matterport 等数据集；
- Qwen 或其他模型权重；
- 实验检查点、缓存、完整结果目录；
- 受许可证或账号权限约束的资产。

模型下载工具接受显式输出目录和可选 Hugging Face token；token 仅从环境变量读取，不写入命令日志、配置文件或 Git。若目标目录已有内容，默认停止并提示，不直接覆盖。

Matterport 等不能公开自动分发的数据，只提供目录结构与人工准备说明。

### 3.4 路径与运行入口

将正式入口中的个人绝对路径替换为以下优先级：

1. 命令行参数；
2. 环境变量；
3. 仓库内相对默认值。

提供不含秘密的 `.env.example` 或等价配置样例。旧实验脚本若仍需保留，必须标明“历史脚本”，不得出现在新的快速开始主流程中。

新的主流程为：

```text
clone -> create environment -> bootstrap third parties
      -> prepare data/model paths -> environment check
      -> CPU unit tests -> Qwen load smoke -> short mapping smoke
```

### 3.5 验证层级

验证分为四层，避免把静态检查误报成完整复现：

1. **当前 Windows 可执行**：Python 语法、配置解析、路径解析、planner 纯 CPU 单元测试、安全扫描。
2. **Linux 无数据检查**：依赖版本、CUDA 可见性、第三方目录和扩展导入。
3. **Linux 模型检查**：Qwen2.5-1.5B-Instruct 能加载并完成一个最小结构化输出。
4. **Linux 完整冒烟**：Replica `office0` 上运行 10--20 个规划/建图步，确认日志、地图和轨迹文件产生。

只有第 4 层在目标 GPU 服务器通过后，才能写“安装后可开始跑 ActiveSGM 冒烟实验”。完整论文复现仍需固定随机种子、预算、数据版本和评测配置。

## 4. 安全边界

发布前执行以下检查：

- 扫描常见密钥、token、密码、私钥和连接串；
- 扫描 `/home/...`、`/data/...`、Windows 用户目录和固定代理地址；
- 阻止模型、数据、检查点、压缩包及异常大文件被暂存；
- 检查 `.gitignore` 覆盖下载资产、缓存、构建产物和本地配置；
- 人工查看 `git diff --cached` 和待推送提交列表；
- 只推送本任务分支，不强推，不改写 `main` 历史，不提交旧本地仓库中的无关改动。

## 5. 计划交付物

- 可复现环境定义与版本说明；
- 第三方依赖获取/构建脚本及来源清单；
- 数据和模型准备说明与安全配置样例；
- 环境自检、安全扫描、CPU 单元测试和 GPU 冒烟入口；
- 重写后的 README 快速开始；
- 一份说明“已在本机验证什么、必须在 GPU 服务器验证什么”的验证记录。

## 6. 验收标准

- 新安装说明中不再要求用户修改作者个人路径。
- 依赖版本不存在已知的 OpenMMLab 明显冲突。
- 仓库不包含数据、权重、凭据、第三方源码副本或个人服务器路径。
- 当前电脑上的静态检查和纯 CPU 测试全部通过。
- 在 Ubuntu 20.04/CUDA 11.7 服务器上，环境自检、Qwen 加载和短程 `office0` 冒烟依次通过；若尚未执行，文档必须明确标记为“待服务器验证”，不能包装成已验证结果。
- 上传采用独立分支；推送前完成差异、秘密和大文件检查。

## 7. 非目标

- 不在本次整理中声称提升语义建图指标或证明论文创新点。
- 不重新训练模型，不运行完整多种子论文实验。
- 不把旧服务器目录完整搬入 GitHub。
- 不自动下载或再分发许可证不允许公开分发的数据。
